1.工作区、暂存区和本地仓库分别是什么？

工作区：电脑中的本机的文件目录
暂存区是：git add 后的文件存放在暂存区（暂存区也是本机目录）
本地仓库：git仓库在本地电脑上的具体实体

2.git add做了什么？
将文件放入暂存区
3.git commit做了什么？
把暂存区的（index）里的内容，打包成一个永久的“快照对象”写入本地仓库
并让当前分支的指针指向这个新的快照

4.git status与git diff有什么区别？
git status:工作区中的文件的状态（是否已经加入缓冲区）-----------错误 片面
git diff  ：已经加入缓冲区的文件与上次相比修改了什么内容。----------错误

git status：宏观的“状态报告”
它只关注文件的状态，不关心具体内容。它会告诉你：
哪些文件被修改了但还没暂存（工作区 vs 暂存区）。
哪些文件已经暂存，准备提交（暂存区 vs 本地仓库）。
哪些文件是全新的，Git 还没管过（未跟踪）。

git diff：微观的“内容对比”
它关注的是文件的具体内容差异。它会逐行展示：
哪些行被删除了（以 - 开头）。
哪些行被新增了（以 + 开头）

5.git diff与git diff --cached有什么区别？
git diff ：比较对象：工作区 vs 暂存区
底层含义：它检查的是“你手头正在修改的内容，是否已经同步到了待发货箱（暂存区）”。
实际场景：你修改了代码，但还没执行 git add。这时执行 git diff，就能看到那些“漏网之鱼”，即你改了但 Git 还没记录下来的具体差异。

git diff --cached：较对象：暂存区 vs 本地仓库（上一次提交）
底层含义：它检查的是“待发货箱（暂存区）里的内容，相对于上一次发货（上一次 commit），到底有哪些新变化”。
实际场景：你已经执行了 git add，文件已经进入了暂存区。这时执行 git diff --cached，就能预览如果你现在执行 git commit，到底会把哪些具体的代码变更写入历史档案。

6.为什么不应该把build/和可执行文件提交到仓库？
Git 的核心价值是管理源代码（Source Code）。
build/ 目录下的 .o 目标文件、可执行文件，都是编译器（如 g++）或构建工具（如 CMake）根据源码和 CMakeLists.txt 自动生成的。
7.gitignore只能忽略未跟踪文件，还是也能自动取消已经被Git跟踪的文件？
只能忽略未跟踪的文件。对于已经被 Git 跟踪（即之前已经 git add 或 git commit 过）的文件，.gitignore 会直接失效，Git 依然会继续监控它的每一次修改。












## Git分支、main和HEAD总结

### 1. Commit（提交）

`commit`是项目在某个时刻的文件快照。

每次执行：

```bash
git commit
```

Git都会创建一个新提交，并分配唯一的哈希编号，例如：

```text
a1b2c3d
```

提交中包括：

* 文件快照；
* 提交说明；
* 作者和时间；
* 上一次提交的编号。

### 2. Branch（分支）

分支不是完整的项目副本。

> 分支是一个可以移动的标签，指向该分支最新的一次提交。

例如：

```text
main → c333
```

表示`main`分支目前的最新提交是`c333`。

在当前分支创建新提交后，分支指针会自动移动：

```text
提交前：main → c333
提交后：main → d444
```

### 3. main分支

`main`是一个普通分支，只是通常被用作项目的主要开发分支。

它和`test`、`feature`等分支的本质相同，区别主要是名称和用途。

### 4. HEAD

`HEAD`表示当前正在操作的位置。

通常情况下，`HEAD`指向当前分支，当前分支再指向最新提交：

```text
HEAD → main → 最新提交
```

因此，在`main`上创建新提交时：

* Git创建新提交；
* `main`移动到新提交；
* `HEAD`仍然指向`main`。

### 5. 创建新分支

执行：

```bash
git switch -c test
```

会：

1. 在当前位置创建`test`分支；
2. 将`HEAD`切换到`test`。

刚创建时：

```text
main → c333
HEAD → test → c333
```

在`test`上创建新提交后：

```text
main → c333
HEAD → test → d444
```

此时`test`向前移动，`main`保持不变。

### 6. 指针的含义

Git中的“指针”不是C/C++内存地址。

它表示一种引用关系：

```text
HEAD指向当前分支
分支指向最新提交
提交指向父提交
```

### 7. 没有首次提交的情况

如果仓库还没有任何提交：

```text
HEAD → main
main → 暂时没有提交
```

第一次执行`git commit`后，`main`才会指向第一个提交。

### 8. 常用查看命令

查看当前分支：

```bash
git branch --show-current
```

查看提交历史和分支位置：

```bash
git log --oneline --decorate --graph --all
```

### 最终记忆

```text
commit = 项目在某个时刻的快照
branch = 指向该分支最新提交的可移动标签
main   = 通常作为项目主线的普通分支
HEAD   = 表示当前正在操作的分支或提交
```

最常见的关系是：

```text
HEAD → main → 最新commit → 上一个commit
```
